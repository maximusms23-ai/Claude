# Phase 31: Token-Spar-Lokalisierung

**Milestone:** v1.4
**Requirements:** LOCAL-01..04
**Depends on:** Nothing (unabhängig von 27–30)

## Goal

`tom-compile --local` nutzt `gemme` statt `claude_agent_sdk` als opt-in Alternative. Ein Eval entscheidet ob Default-Switch sinnvoll wäre. `tom-lint --structural-only` ist als launchd-tauglicher Default dokumentiert.

## Tasks

1. `tom_tools/compile_local.py` — neues Modul mit strukturierter JSON-Response
2. `bin/tom-compile` um `--local` flag erweitert (dispatcht zu compile_local)
3. Eval-Run: real log (FLUSH_OK-only) + synthetic log (rich content) via `--output-dir` Sandbox
4. Eval-Report in `Gemma/eval/results/v1.4-compile-local-vs-claude.md`
5. `CLAUDE.md` — tom-compile --local + tom-lint --structural-only als launchd-Default dokumentiert
6. Maximus_OS-Issue für Entscheidungsstand

## Key Design Decision

**Structured-Data-First statt Markdown-in-JSON:** Erste Iteration ließ gemme fertige Markdown-Strings mit `\n`-Escaping in JSON returnen → Parse-Errors bei multi-line content. Zweite Iteration: gemme returnt flache Daten (slug/title/kernpunkte[]/details/related[]), Python rendert das Markdown deterministisch. Robust, kein Parse-Risiko mehr.

## Success Criteria

1. ✓ `tom-compile --local --file <log>` läuft fehlerfrei durch
2. ✓ `--output-dir` funktioniert als Sandbox
3. ✓ Real-Log (FLUSH_OK) → 0 Artikel (korrekte Entscheidung)
4. ✓ Synthetic-Log → 2+ Artikel ohne Halluzinationen
5. ✓ Eval-Report dokumentiert beide Modi + Entscheidung
6. ✓ CLAUDE.md dokumentiert `--local` + `tom-lint --structural-only` als launchd-Default
7. ✓ Default bleibt `claude_agent_sdk` — `--local` ist opt-in

- State-Management (`state.json`) für --local Modus
- Update-Erkennung (existing articles modifizieren)
