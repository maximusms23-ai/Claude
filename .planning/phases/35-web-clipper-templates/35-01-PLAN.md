# Phase 35: Web-Clipper-Template-System

**Milestone:** v1.4.1 — Bridge vor v1.5
**Requirements:** CLIP141-01..06
**Depends on:** Phase 33 (Doku-Routine) + Phase 34 (Plugin-Audit)

## Goal

Obsidian Web Clipper schreibt ab jetzt typ-spezifische Clippings (7 Typen: Artikel, Paper, Video, Dokument, Social-Post, Rezept, Werkzeug) mit Tom-konformem Frontmatter und Auto-Routing in `Clippings/<Typ>/`. `tom-clip-enrich` bleibt on-demand-Workflow.

## Tasks

### Task 1 — Ordnerstruktur (CLIP141-02)

- `$TOM_VAULT/99_Vorlagen/web-clipper/` anlegen
- 7 Ziel-Ordner unter `$TOM_VAULT/Clippings/`: Artikel, Paper, Videos, Dokumente, Social, Rezepte, Werkzeuge
- Pro Ziel-Ordner: README-Stub mit Typ-Erklärung (damit Obsidian die leeren Ordner anzeigt)

### Task 2 — 7 Templates (CLIP141-01)

- `Artikel.md` — Blog-Posts, News
- `Paper.md` — Akademische Paper (+ venue/arxiv_id/doi Zusatz-Pflege)
- `Video.md` — YouTube, Vimeo (+ duration Zusatz-Pflege)
- `Dokument.md` — Amtliche Online-Dokumente (+ herausgeber/gueltig_ab/gueltig_bis)
- `Social-Post.md` — Twitter, Mastodon, Threads
- `Rezept.md` — Kochrezepte (+ portionen/zeit/kategorie_kueche)
- `Werkzeug.md` — Software, GitHub (+ lizenz/sprache/stars)

Jedes Template hat Tom-konformes Frontmatter (`title`, `created`, `type`, `source`, `tags`, `enriched: false`, `suggested_wiki_category: ""`) und Body mit `{{title}}`, `{{url}}`, `{{domain}}`, `{{content}}` Variablen (Obsidian Web Clipper Syntax).

### Task 3 — README (CLIP141-03, CLIP141-06)

- `99_Vorlagen/web-clipper/README.md` mit:
  - Template-Tabelle (7 Zeilen)
  - Browser-Extension-Setup Schritt-für-Schritt
  - Variablen-Referenz
  - `tom-clip-enrich`-Aufruf-Beispiele
  - Privacy-Check
  - Troubleshooting
- Hinweis: Variablen-Syntax der Extension ist illustrativ — bei erstem Setup getestet und ggf. angepasst

### Task 4 — CLAUDE.md Update (CLIP141-05)

- "Ingesting New Sources" um Web-Clipper-Flow-Subsektion ergänzt
- `tom-clip-enrich`-Aufruf dokumentiert

### Task 5 — Smoke-Test (CLIP141-04) — Maxim-Handoff

- **Status:** Prepared-pending-maxim-smoke-test (analog zu Phase 29 UI-Handoff-Pattern)
