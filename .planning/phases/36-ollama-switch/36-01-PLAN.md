# Phase 36: Lokaler Ollama-Switch für Claude Code

**Milestone:** v1.5 — erste Phase (Opener, formeller `/gsd:new-milestone` Kickoff folgt)
**Requirements:** LOCAL-05 (terminal-invoked local-LLM-Switch), PRIVACY-03 (opt-in, kein Default-Override)
**Depends on:** Phase 31 (Token-Spar-Lokalisierung), Phase 34 (Plugin-Audit)

## Goal

Maxim kann in `/Users/maxim/Claude` mit einem einzigen Shell-Kommando (`nutze-ollama`) Claude Code's Backend temporär auf lokales Ollama umleiten — mit beiden Modellen `gemme` (Chat/Wiki) und `qwen2.5-coder` (Tool-Use) verfügbar via Claude Code's `/model`-Picker. Rückkehr mit `nutze-claude`. Zusätzlich `tom-local` als Subshell-/One-Shot-Variante. Default bleibt Claude Cloud — GSD-Workflows und Tom-Development laufen unverändert weiter, bis Maxim bewusst lokal schaltet.

## Key Decision — Model-Aliasing statt Custom-Namen im Picker

Claude Code's `/model`-Picker ist hardcoded auf Anthropic-Modellnamen (Opus/Sonnet/Haiku). Custom-Namen wie "gemme" tauchen **nicht** im Picker auf. **Lösung**: Claude Code Router aliased:
- `claude-*-opus-*` → `qwen2.5-coder:latest` (Tool-Use-Modell)
- `claude-*-haiku-*` / `background` → `gemme:latest` (Chat-Modell)

Im Ollama-Modus entspricht `/model opus` dann qwen2.5-coder, `/model haiku` gemme. Dokumentiert prominent im `ollama-status`-Output + CLAUDE.md.

## Recherche-Findings

1. **Gemma4 Tool-Use verifiziert broken** ([ollama#15402](https://github.com/ollama/ollama/issues/15402)). Deswegen Qwen2.5-coder als zweites Modell.
2. **Qwen3.5-coder existiert nicht in Ollama Library** (`pull model manifest: file does not exist`). Fallback auf `qwen2.5-coder:latest` — 4.7 GB, already pulled.
3. **Claude Code Router** (`@musistudio/claude-code-router`) installiert via npm global, binary: `/opt/homebrew/bin/ccr`. Commands: `start`, `activate`, `status`, `code`. `ccr activate` emittiert env vars für Shell-Integration — exakt unser Use-Case.
4. **`code` CLI nicht im PATH** — VSCode Extension gefunden via `~/.vscode/extensions/`: `warm3snow.vscode-ollama-1.2.1` (Chat-Panel).
5. **Greenfield**: Keine vorhandene Routing-Infra, keine `ANTHROPIC_BASE_URL`-Referenzen im Repo.

## Tasks

### Task 1 — Claude Code Router Setup (LOCAL-05-01)

- `~/.claude-code-router/config.json` schreiben mit Providers + Router-Mapping
- `ccr start` → Daemon im Hintergrund
- `ccr status` → Bestätigung
- Reference-Copy im Repo unter `.planning/phases/36-ollama-switch/ccr-config.reference.json` (für Dokumentation + Wiederherstellung)

### Task 2 — Shell-Funktions-Library (LOCAL-05-02)

- `bin/nutze-ollama.sh` — sourced Library mit Funktionen:
  - `nutze-ollama` — Preflight + `eval "$(ccr activate)"` im current shell, Warning-Echo
  - `nutze-claude` — unset ANTHROPIC_BASE_URL/ANTHROPIC_API_KEY, Echo
  - `ollama-status` — zeigt aktueller Modus, Ollama-Health, CCR-Daemon, Modelle, Aliasing-Mapping
- Idiom: `#!/usr/bin/env bash` + `set -uo pipefail` (nicht `-e` in sourced lib, damit Funktionen nicht die Parent-Shell killen)
- Preflight: `ollama`-Binary + `ollama list` + `ccr`-Binary + CCR-Daemon-Check (idempotent starten falls tot)

### Task 3 — Wrapper-Script `bin/tom-local` (LOCAL-05-03)

- Executable Script, nutzt `nutze-ollama.sh` via source
- **No args**: Subshell mit env gesetzt (`zsh -i` im env)
- **Mit args**: One-Shot `env ... "$@"` (z.B. `tom-local claude`)
- Preflight gleich wie `nutze-ollama`-Funktion
- Symlink `~/bin/tom-local` → `/Users/maxim/Claude/bin/tom-local` (Konvention analog tom-ask)

### Task 4 — `~/.zshrc` Integration (LOCAL-05-04, consent-gated)

- **EINE Zeile** anhängen, mit expliziter Bestätigung:
  ```bash
  [[ -f "$HOME/Claude/bin/nutze-ollama.sh" ]] && source "$HOME/Claude/bin/nutze-ollama.sh"
  ```
- Guarded Source → kein Fehler bei fehlendem File
- Rollback trivial: Zeile löschen
- Ohne Consent: dokumentieren und skippen, Funktionen nur verfügbar nach manuellem `source`

### Task 5 — CLAUDE.md Dokumentation (LOCAL-05-05)

- Neue Sektion "Lokaler Ollama-Modus (seit v1.5 Phase 36)" unter "Commands"
- Kommando-Referenz: `nutze-ollama`, `nutze-claude`, `ollama-status`, `tom-local`, `tom-local claude`
- Aliasing-Erklärung (Opus→qwen, Haiku→gemme)
- **Known Limitations** prominent: Gemma-Tool-Use broken (nur chat), qwen2.5 schwächer als Claude, Node-Dep, CCR-Daemon-RAM
- Rollback-Hinweise

### Task 6 — VSCode Extension Setup (LOCAL-05-06)

- `warm3snow.vscode-ollama-1.2.1` identifiziert
- Settings in `~/.vscode/extensions/warm3snow.vscode-ollama-1.2.1/` prüfen: welche Config-UI vorhanden, File-I/O-Capabilities?
- Dokumentation der tatsächlichen Capabilities in CLAUDE.md Plugin-Landscape
- Privacy-Hinweis analog ADR-001 falls Vault-Zugriff

### Task 7 — Smoke-Tests (LOCAL-05-07)

Critical Pass/Fail-Gate: Tool-Use mit qwen2.5-coder im Ollama-Modus.

1. Cloud-Default: Fresh shell, `echo $ANTHROPIC_BASE_URL` → leer
2. `nutze-ollama` → env gesetzt, Warning gezeigt
3. `ollama-status` → daemon up, models listed, aliasing shown
4. Chat-Query via `ccr code "Was ist 2+2?"` → Antwort von gemme/qwen
5. **Tool-Use-Test**: `ccr code "liste dateien in /tmp"` → muss Tool-Call produzieren (LS)
6. `nutze-claude` → env weg
7. `tom-local --version` → subshell mit env
8. `tom-local claude --version` → one-shot

**Scheitert Test 5** → qwen2.5-coder-Tool-Use ist nicht einsatzbereit, Phase endet als "Chat-Only-Modus dokumentiert" statt "Tool-Use funktioniert".
