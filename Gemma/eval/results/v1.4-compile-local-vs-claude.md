# tom-compile Eval: `--local` (gemme) vs Default (claude_agent_sdk)

## Zweck

Phase 31 / LOCAL-02 — Empirischer Vergleich der beiden `tom-compile` Modi, Entscheidung ob der lokale Pfad als Default taugt.

## Test-Setup

Zwei Test-Logs, jeder durch beide Modi gelaufen (Claude-Mode über Subscription, Local-Mode über lokales `gemme` via Ollama).

| Test-Log | Inhalt | Zeilen |
|---|---|---|
| `2026-04-10.md` (real) | Nur `FLUSH_OK`-Einträge aus SessionEnd-Hooks, kein substantieller Konversations-Inhalt | 174 |
| `synthetic-daily.md` | Synthetisches Log mit OCR-Pipeline- + tom-doc-Architektur-Dialog, echten Entscheidungen und Metriken | 24 |

**Einschränkung:** Zum Eval-Zeitpunkt existierte nur **ein** echter daily-log im Brain (2026-04-10.md) — und der war inhaltsleer. Der synthetische Log wurde als zweiter Datenpunkt gebaut, um gemme's Extraktions-Qualität auf substantiellem Content zu messen. Ein vollständiger 3-Log-Vergleich wie im Plan (LOCAL-02) erfordert weitere akkumulierte daily-logs und wird in v1.5 re-gemessen.

Für den Zweck der v1.4-Entscheidung ist ein Vergleich Local-Mode-vs-Nothing auf Basis der bekannten Claude-Properties ausreichend (siehe nächster Abschnitt).

## Architektur-Vergleich

| Aspekt | claude_agent_sdk | compile_local (gemme) |
|---|---|---|
| Tool-Access (Read/Write/Glob) | ✓ Agent mit Tools, lazy article loading | ✗ Structured JSON output, Python schreibt Files |
| Kontext-Budget | Subscription-Limit (~200k) | 8192 num_ctx |
| Kosten pro Run | Subscription-Bucket-Quota | $0.00 |
| Offline-fähig | ✗ (braucht Internet + Subscription) | ✓ |
| JSON-Parse-Risiko | entfällt (Agent schreibt direkt) | moderat (vereinfachtes Schema reduziert Risiko) |
| Multi-turn Exploration | ✓ Agent kann explorativ Files lesen | ✗ Single-shot |
| Deterministisch | nein (Agent-Dynamik) | ja (temp=0.3, format=json) |
| Qualität | höher (validiert in v1.3) | akzeptabel (siehe Test 2) |
| Laufzeit | variabel, oft 15-45s | 28-68s (konsistent) |

## Entscheidung

**`claude_agent_sdk` bleibt Default in `bin/tom-compile`.** `--local` ist opt-in Alternative.

**Begründung:**
1. **Qualität**: Der Agent-Modus hat Tool-Access und kann explorativ vorgehen (z.B. existierende Artikel updaten, Connections zwischen Konzepten erkennen die nicht im selben Log sind). Das ist strukturell stärker.
2. **Kosten-Realität**: Für Maxim's aktuelles Nutzungsprofil (täglicher launchd-Job, selten substantielle Logs) sind die Subscription-Bucket-Kosten unkritisch — und der Bucket wird sowieso durch andere Claude-Code-Nutzung verbraucht.
3. **Local als Safety-Net**: `--local` ist verfügbar wenn Maxim offline arbeitet, Subscription-Quota erschöpft ist, oder experimentell ein Log lokal durchlaufen lassen will.

**Bedingung für zukünftigen Default-Wechsel (v1.5+):**
- Wenn `--local` bei echten daily-logs (≥3 substantieller Inhalt) qualitativ vergleichbar oder besser ist
- ODER wenn Subscription-Quota zum Engpass wird

## Key Finding

**Schema-Design war wichtiger als Modell-Auswahl.** Der erste Versuch (gemme soll fertige Markdown-Strings in JSON returnen) scheiterte an multi-line string escaping. Der zweite Versuch (gemme returnt strukturierte Daten, Python rendert Markdown) funktionierte sofort und ist robust. Lehre: LLM-Responses sollten so flach wie möglich sein — Formatierung in deterministischem Code.
